margin — a local feedback loop for visual docs

01Transport — daemon & queue

A tiny localhost daemon owns the queue. Docs POST annotations to it; agents drain it with the same CLI everywhere — margin list, margin reply, margin resolve. No harness-specific code lives in the doc itself.

The daemon writes every event to a JSONL journal under ~/.margin, so a crashed session can recover pending feedback without a second process.

02Anchoring — fuzzy, not fixed

The injected layer captures the exact quote, forty characters of context on each side, and the heading trail above the selection. Nothing is stored as a position — every anchor is resolved lazily against the file as it exists right now.

margin locate re-parses the current HTML and returns a line range plus a confidence: exact, normalized, partial, or lost. Low confidence means the agent asks before editing.

03Status & replies

Annotations carry a status — unread, read, resolved — so the page can tell you whether the agent has seen your note. Replies land in the same thread, and the page live-reloads over SSE when the agent edits the file.
